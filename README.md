# Клинический компас

Веб-приложение для хакатона: кабинеты врача и пациента, карточки, приглашения, дневник настроения и чат с локальной языковой моделью.

## Возможности

- Регистрация по электронной почте и паролю, две роли: врач и пациент.
- Прикрепление пациента к врачу через одноразовую ссылку или QR-код.
- Список пациентов, карточки, общая информация и отдельные личные заметки врача.
- Редактирование профилей; пациент видит профиль своего врача.
- Дневник настроения: оценка 1–5, чувства и заметка. Доступ врачу включается отдельно для каждой записи.
- Личный чат с Qwen3 1.7B через WebLLM, потоковая выдача ответов и сохранение истории.
- Каталог DASS-42, PHQ-9, GAD-7, MFQ и POMS с описаниями для врача, еженедельными назначениями и историей результатов.
- Изолированное демо-пространство с вымышленными пациентами и переключением роли.

Интерфейс и логика приложения соответствуют исходной версии MVP. Настройки сборки и размещения подготовлены для самостоятельного запуска.

## Быстрый запуск

Нужны Node.js **22.13 или новее** и **pnpm 11.25.0**. Установите pnpm, если его ещё нет:

```sh
npm install --global pnpm@11.25.0
```

Затем в каталоге репозитория:

```sh
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

Откройте [localhost:5173](http://127.0.0.1:5173). Для знакомства нажмите «Открыть демо-кабинет». Данные демо создаются только по нажатию кнопки; доступ к чужим аккаунтам не открывается.

Для локального запуска аккаунт Cloudflare и ключи API не требуются. Wrangler эмулирует Workers и D1 на компьютере. Локальная база находится в `.wrangler/state` и исключена из Git. Повторный запуск `pnpm db:migrate` применяет только новые миграции.

## Сборка и проверки

```sh
pnpm check
pnpm build
pnpm preview
```

Собранное приложение доступно на [localhost:8787](http://127.0.0.1:8787). Пока оно запущено, в другом терминале:

```sh
pnpm test:api
pnpm test:chat
pnpm test:assessments
node tests/assessment-catalogue.mjs http://127.0.0.1:8787 --legacy-local-result
```

56 проверок основных сценариев и 99 проверок дневника и чата охватывают регистрацию, приглашения, доступ к данным, исключение личных заметок из ответов пациенту, публикацию записей врачу, смену врача, пагинацию, повторы и конкурентные запросы. Тесты создают вымышленные аккаунты в локальной базе. Запускайте их на локальном приложении, а не на рабочем сервере.

Дополнительно 102 проверки тестов охватывают ключ DASS-42, валидацию 42 ответов, назначения, паузы, доступ только лечащего врача, повторные и конкурентные отправки, недельный срок и смену врача.

Генерация LLM проверяется отдельно в браузере с WebGPU. API-тесты проверяют сохранение готовых ответов и разграничение доступа.

## Назначения тестов

Врач: карточка пациента → «Назначить тест» → выберите методику и частоту → «Назначить тест». Доступны 1, 3, 7, 14, 30 дней и свой целый интервал от 1 до 365 дней. Первый опросник доступен сразу; после отправки следующая попытка открывается через выбранное число × 24 часа. Пропущенные циклы не создают очередь опросников. Назначение можно приостановить и возобновить.

Частоту существующего назначения можно изменить кнопкой «Сохранить частоту». Следующая дата пересчитывается от последнего прохождения: если срок уже прошёл, тест доступен сразу; если результатов ещё нет, доступность сохраняется. Пауза сохраняется при смене частоты. Интервал копируется в результат: прежние квитанции и повторные отправки сохраняют исходную дату даже после изменения расписания врачом. Миграция `0004_funny_pride.sql` сохраняет для старых записей интервал 7 дней.

Пациент: откройте «Мои тесты» → «Пройти тест». Ответьте на вопросы выбранного теста (до 6 на странице), затем нажмите «Отправить ответы врачу». Черновик остаётся только в текущем экране до отправки. Кабинет показывает подтверждение и следующую дату. Врач видит последние 100 результатов с показателями соответствующего теста; автоматических диагнозов и уведомлений по почте нет.

Используется полная DASS-42 в переводе Фаттахова и соавт. (2025), таблица 1 предоставленной статьи. [Русский перевод](https://dass.psy.unsw.edu.au/Russian/Fattakhov/Fattakhov%20Russian.htm), [официальный ключ](https://dass.psy.unsw.edu.au/Download%20files/Dass_template.pdf), [условия компьютерного применения](https://dass.psy.unsw.edu.au/DASSFAQ.htm). Каждая шкала — сумма 14 ответов, 0–42; коэффициент DASS-21 не применяется. Вычисленные баллы доступны врачу, пациент получает только подтверждение. Интерпретация остаётся за специалистом.

### Дополнительные методики

| Тест | Для чего | Период оценки | Версия и подсчёт |
| --- | --- | --- | --- |
| PHQ-9 | Депрессивные симптомы и их динамика | 2 недели | 9 ответов 0–3, сумма 0–27 |
| GAD-7 | Тревожные симптомы и беспокойство | 2 недели | 7 ответов 0–3, сумма 0–21 |
| MFQ | Настроение, удовольствие, самоотношение у взрослых | 2 недели | Уточнённая русская адаптация: 20 ответов 0–2, сумма 0–40 |
| POMS | Положительные и отрицательные эмоции | Неделя, включая сегодня | Уточнённая русская адаптация: 38 ответов 0–4; 29 отрицательных (0–116), 9 положительных (0–36), разность (−36…116) |

Повторение раз в неделю не меняет исходный период оценки: окна PHQ-9, GAD-7 и MFQ перекрываются. На карточках выбора указаны назначение, версия, период, число пунктов, а в раскрывающемся разделе — ключ и первоисточники. Автоматические диагнозы и пороги тяжести не добавлены.

PHQ-9: текст из приложения [Золотаревой, 2023](https://psyjournals.ru/journals/cpse/archive/2023_n4/Zolotareva), на которое ссылается предоставленная работа [Говорова и соавт., 2026](https://doi.org/10.51217/npsyresearch_2026_06_01_10). GAD-7: приложение к предоставленной [адаптации Золотаревой, 2023](https://doi.org/10.17759/cpp.2023310402).

MFQ и POMS: [Шилко и соавт., 2026](https://doi.org/10.51217/npsyresearch_2026_06_01_02), приложения 1–4 и обсуждение уточнённых структур на с. 43–45. В MFQ сохранены исходные пункты 1, 2, 5, 9, 10, 11, 13, 14, 15, 16, 17, 20, 21, 22, 23, 24, 25, 27, 28, 29. В тексте есть опечатка «12 исключённых пунктов», но перечислены 13; перечисление и итоговые 20 пунктов согласуются. Это не полная MFQ-33 и не SMFQ-13: их нормативы не переносятся.

В POMS исключены исходные пункты 32 «Озадаченный» и 33 «Яростный»; формулировки и порядок остальных взяты из бланка приложения 2. Положительные пункты исходного бланка: 5, 6, 9, 13, 19, 25, 31, 34, 37. Общий показатель вычисляется как отрицательные минус положительные, согласно разделу методик и числам таблицы 1 (например, 12,3 − 21,2 = −8,9); одна фраза в статье ошибочно описывает обратный порядок. Отрицательный общий результат допустим. Это не исходная POMS-65.

Новая миграция `0003_parallel_gunslinger.sql` добавляет nullable `scores_json`, сохраняя прежние записи. У старых DASS-42 результатов читаются прежние три колонки; у новых — именованные показатели в JSON. Старые колонки для других тестов не используются. `tests/assessment-catalogue.mjs` проверяет пределы, каждый пункт POMS, отрицательную разность, пять форм, повторную отправку, разделение доступа и совместимость с прежним DASS-42. Флаг `--legacy-local-result` меняет только созданную тестом локальную запись.

Подсчёт выполняется на сервере; присланные клиентом баллы игнорируются. Результат и новая дата сохраняются одной транзакцией. Уникальный цикл и идентификатор отправки защищают от дублей. Удаление связи с врачом приостанавливает назначения; другой врач не получает прежние результаты. При повторном подключении к прежнему врачу история сохраняется, назначение возобновляется явно.

Каталог и версии тестов находятся в `lib/assessments.ts`, серверные маршруты — в `lib/assessment-api.ts`, интерфейс — в `app/components/Assessments.tsx`. Для новых шкал добавляйте отдельные определения, правила проверки и подсчёта; сохраняйте версии уже использованных опросников. Миграция `0002_smiling_morbius.sql` добавляет таблицы назначений и результатов, не изменяя существующие записи.

## Сон и активность: импорт выгрузок

Пациент: «Сон и активность» → выбрать файл → выбрать источник каждой метрики и даты → проверить таблицу → «Сохранить выбранные данные». По умолчанию данные видит только пациент. Отдельная кнопка открывает текущему врачу доступ к сохранённым и будущим показателям. Доступ отключается вручную и при удалении связи с врачом; при повторном подключении автоматически не восстанавливается. Врач видит данные в карточке пациента.

Поддерживаемые форматы:

- Apple «Здоровье»: ZIP с `export.xml` или сам XML. [Инструкция Apple](https://support.apple.com/ru-ru/guide/iphone/iph5ede58c3d/ios).
- Android 14+: Health Connect → Управление данными → Резервное копирование и восстановление → Экспорт по расписанию. ZIP с `health_connect_export.db` или сама база. [Инструкция Android](https://support.google.com/android/answer/15323271?hl=ru). Данные приложения часов должны быть доступны в Health Connect. Google Fit Takeout не поддерживается.

Файл читается в Web Worker на устройстве: ZIP через fflate, SQLite через sql.js со встроенным WASM. На сервер передаются только выбранные даты, три суточных значения и подписи источников. Полный архив, пульс, маршруты, медицинские записи и заметки не загружаются. Лимиты: 100 МБ до/после распаковки, до 500 000 поддерживаемых записей, до 366 выбранных дней; сохранение порциями по 30 дней. При сбое часть порций могла сохраниться; повтор обновляет совпадающие дату/приложение/метрику без прибавления. Отсутствующие показатели не заменяются нулями и не затирают прежние значения.

Выбирается один источник на метрику, чтобы телефон и часы не суммировались. Apple и Android отображаются отдельно. Шаги через полночь распределяются пропорционально длительности интервала: это приближение, точное время отдельных шагов экспорт не содержит. Сон и активность делятся по календарным дням со смещением часового пояса начала записи. Точные дубли удаляются, пересекающиеся интервалы сна объединяются. В Android при отсутствии часового пояса используется UTC.

Apple: шаги `HKQuantityTypeIdentifierStepCount` (count); сон только Asleep/AsleepUnspecified/Core/Deep/REM, без InBed/Awake; активность `HKQuantityTypeIdentifierAppleExerciseTime` (min). Android: шаги `steps_record_table`; сон — `sleep_session_record_table` минус стадии 1, 3, 7 из `sleep_stages_table`. Если стадий нет, используется длительность сессии с пояснением в интерфейсе. Активность Android — время тренировок `exercise_session_record_table` минус отдых/паузы 66, 67 из `exercise_segments_table`, а не вся активность дня. Пересекающиеся тренировки одного источника объединяются.

Формат Android проверен по [AOSP ExportManager](https://android.googlesource.com/platform/packages/modules/HealthFitness/+/refs/heads/main/service/java/com/android/server/healthconnect/exportimport/ExportManager.java) и [datatypehelpers](https://android.googlesource.com/platform/packages/modules/HealthFitness/+/refs/heads/main/service/java/com/android/server/healthconnect/storage/datatypehelpers/). Это внутренняя схема; неизвестные обязательные поля отклоняются с понятной ошибкой. Будущие версии ОС могут требовать нового адаптера.

Это ручной импорт. Автоматическая синхронизация и мобильные разрешения HealthKit/Health Connect не реализованы. Проверки используют синтетические выгрузки; реальная пользовательская выгрузка ещё не проверялась. Показатели устройств отображаются без автоматической клинической интерпретации.

```sh
node tests/health-import.mjs
node tests/schedules-health.mjs
```

Первый тест создаёт вымышленные Apple/Android ZIP в игнорируемом `outputs/health-fixtures/` для браузерной проверки. Второй проверяет частоту, историю квитанций, импорт, отсутствие дублей, доступ врача и его отзыв при переподключении.

## Подключение iPhone через «Команды»

В разделе «Сон и активность» есть инструкция из четырёх шагов: добавить подписанный файл команды, запустить её из кабинета пациента, проверить получателя и разрешения, затем выбрать источники и сохранить предпросмотр. Для повторного подключения доступна ссылка сразу к запуску. Раздел «Если что-то не получилось» объясняет установку, запуск из редактора, истёкший код и отсутствие отдельных показателей; запасной путь ведёт к импорту архива.

В предпросмотре подсказки объясняют выбор источника для шагов, сна и активности. Если источников несколько, требуется явный выбор. Единственный источник выбирается автоматически; отсутствие записей означает «Не импортировать». Перед сохранением интерфейс указывает, для каких показателей выбор ещё не сделан. Значения телефона и часов не суммируются.

Команда привязана к опубликованному адресу `clinical-compass-v2.navyelk1024.chatgpt.site`. Настоящий запуск следует проверять на iPhone с этим сайтом; локальный сервер позволяет проверить интерфейс, импорт синтетического архива и API. Изменения инструкции не меняют подписанный файл команды, разрешения, правила подсчёта или доступ врача.

Проверка на iPhone перед выпуском: установить команду, запустить из кабинета, сверить имя и адрес получателя, предоставить выбранные разрешения, дождаться предпросмотра, проверить источники и даты, сохранить. Также проверить отказ в разрешении и повторный запуск. Названия системных окон могут отличаться между версиями iOS. Инструкция опирается на текущий генератор команды; автоматические тесты не заменяют эту проверку на устройстве.

## Бесплатная модель

В кабинете пациента откройте «Чат и дневник» → «Поговорить» → «Загрузить бесплатную модель».

[Qwen3 1.7B](https://huggingface.co/Qwen/Qwen3-1.7B) работает на устройстве через [WebLLM](https://webllm.mlc.ai/docs/user/basic_usage.html), без API-ключа и оплаты запросов. Первый запуск скачивает около 1 ГБ; для модели нужны WebGPU и примерно 2–3 ГБ свободной памяти GPU. Лучше использовать актуальный Chrome или Edge на компьютере. При отсутствии WebGPU дневник и история остаются доступны.

Модель получает ограниченную недавнюю историю переписки, без медицинской карты и дневника. Генерация выполняется в браузере, затем сообщения сохраняются на сервере приложения в аккаунте пациента. Переписка недоступна врачам и не отправляется поставщику модели. Файлы модели загружаются с Hugging Face, исполняемый модуль — из официального репозитория MLC.

## Размещение в своём Cloudflare

В репозитории настроены Cloudflare Workers и D1. Значение `database_id` в `wrangler.jsonc` — заглушка для локального запуска.

1. Авторизуйтесь и создайте собственную базу:

   ```sh
   pnpm exec wrangler login
   pnpm exec wrangler d1 create clinical-compass
   ```

2. Замените `database_id` в `wrangler.jsonc` на ID созданной базы. При необходимости задайте свой `account_id` и имя Worker. Не записывайте токены в файлы репозитория.
3. Примените миграции к своей удалённой базе, пересоберите приложение и опубликуйте:

   ```sh
   pnpm db:migrate:remote
   pnpm build
   pnpm deploy
   ```

Команда публикации выведет адрес Worker. Это отдельное размещение в вашем аккаунте; локальная и удалённая базы независимы. Условия и лимиты хостинга определяются тарифом Cloudflare.

## Границы MVP

Используйте вымышленные данные для демонстрации на хакатоне. Нет проверки квалификации врача, подтверждения почты, восстановления пароля, клинической интерпретации шкал, аудита действий и подготовки к работе с реальными медицинскими данными.

Пароли хешируются PBKDF2-SHA256 с индивидуальной солью; в базе сохраняются хеши токенов сессии. Права проверяются на сервере. Смена аккаунта синхронизируется между вкладками; запросы устаревшего кабинета отклоняются до изменения данных. Сессии используют HttpOnly и SameSite, а на HTTPS — Secure. Для изменений проверяется Origin; предусмотрены ограничения частоты запросов.

Модель может ошибаться. Чат не назначает лечение, не уведомляет врача и не является экстренной помощью. Простые правила перехватывают некоторые сообщения о непосредственной опасности и лекарствах; такие ответы подписаны как служебные сообщения, а не ответы модели. Это не полноценная клиническая оценка риска.
