# Клинический компас

Веб-приложение для хакатона: кабинеты врача и пациента, карточки, приглашения, дневник настроения и чат с локальной языковой моделью.

## Возможности

- Регистрация по электронной почте и паролю, две роли: врач и пациент.
- Прикрепление пациента к врачу через одноразовую ссылку или QR-код.
- Список пациентов, карточки, общая информация и отдельные личные заметки врача.
- Редактирование профилей; пациент видит профиль своего врача.
- Дневник настроения: оценка 1–5, чувства и заметка. Доступ врачу включается отдельно для каждой записи.
- Личный чат с Qwen3 1.7B через WebLLM, потоковая выдача ответов и сохранение истории.
- Изолированное демо-пространство с вымышленными пациентами и переключением роли.

Интерфейс и логика приложения соответствуют исходной версии MVP. Настройки сборки и размещения подготовлены для самостоятельного запуска.

## Быстрый запуск

Нужны Node.js **22.13 или новее** и **pnpm 11.25.0**. Установите pnpm, если его ещё нет:

```sh
npm install --global pnpm@11.25.0
```

Затем в каталоге репозитория:

```sh
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

Откройте [localhost:5173](http://127.0.0.1:5173). Для знакомства нажмите «Открыть демо-кабинет». Данные демо создаются только по нажатию кнопки; доступ к чужим аккаунтам не открывается.

Для локального запуска аккаунт Cloudflare и ключи API не требуются. Wrangler эмулирует Workers и D1 на компьютере. Локальная база находится в `.wrangler/state` и исключена из Git. Повторный запуск `pnpm db:migrate` применяет только новые миграции.

## Сборка и проверки

```sh
pnpm check
pnpm build
pnpm preview
```

Собранное приложение доступно на [localhost:8787](http://127.0.0.1:8787). Пока оно запущено, в другом терминале:

```sh
pnpm test:api
pnpm test:chat
```

44 проверки основных сценариев и 99 проверок дневника и чата охватывают регистрацию, приглашения, доступ к данным, исключение личных заметок из ответов пациенту, публикацию записей врачу, смену врача, пагинацию, повторы и конкурентные запросы. Тесты создают вымышленные аккаунты в локальной базе. Запускайте их на локальном приложении, а не на рабочем сервере.

Генерация LLM проверяется отдельно в браузере с WebGPU. API-тесты проверяют сохранение готовых ответов и разграничение доступа.

## Бесплатная модель

В кабинете пациента откройте «Чат и дневник» → «Поговорить» → «Загрузить бесплатную модель».

[Qwen3 1.7B](https://huggingface.co/Qwen/Qwen3-1.7B) работает на устройстве через [WebLLM](https://webllm.mlc.ai/docs/user/basic_usage.html), без API-ключа и оплаты запросов. Первый запуск скачивает около 1 ГБ; для модели нужны WebGPU и примерно 2–3 ГБ свободной памяти GPU. Лучше использовать актуальный Chrome или Edge на компьютере. При отсутствии WebGPU дневник и история остаются доступны.

Модель получает ограниченную недавнюю историю переписки, без медицинской карты и дневника. Генерация выполняется в браузере, затем сообщения сохраняются на сервере приложения в аккаунте пациента. Переписка недоступна врачам и не отправляется поставщику модели. Файлы модели загружаются с Hugging Face, исполняемый модуль — из официального репозитория MLC.

## Размещение в своём Cloudflare

В репозитории настроены Cloudflare Workers и D1. Значение `database_id` в `wrangler.jsonc` — заглушка для локального запуска.

1. Авторизуйтесь и создайте собственную базу:

   ```sh
   pnpm exec wrangler login
   pnpm exec wrangler d1 create clinical-compass
   ```

2. Замените `database_id` в `wrangler.jsonc` на ID созданной базы. При необходимости задайте свой `account_id` и имя Worker. Не записывайте токены в файлы репозитория.
3. Примените миграции к своей удалённой базе, пересоберите приложение и опубликуйте:

   ```sh
   pnpm db:migrate:remote
   pnpm build
   pnpm deploy
   ```

Команда публикации выведет адрес Worker. Это отдельное размещение в вашем аккаунте; локальная и удалённая базы независимы. Условия и лимиты хостинга определяются тарифом Cloudflare.

## Структура

| Каталог или файл | Назначение |
| --- | --- |
| `app/page.tsx` | Кабинеты, профили и карточки |
| `app/components/PatientChat.tsx` | Чат и дневник пациента, записи для врача |
| `app/api/[...path]/route.ts` | Серверное API и проверка прав |
| `lib/security.ts` | Хеширование паролей и токенов |
| `lib/llm.worker.ts` | Запуск модели в отдельном Web Worker |
| `lib/use-local-model.ts` | Загрузка модели, прогресс и обработка ошибок |
| `db/schema.ts`, `drizzle/` | Схема базы и SQL-миграции |
| `server/worker.ts` | Входная точка сервера |
| `wrangler.jsonc`, `vite.config.ts` | Настройки запуска, базы и сборки |
| `tests/` | Интеграционные проверки API |

Стек: React, TypeScript, Vinext/Vite, Cloudflare Workers, D1, Drizzle и WebLLM. Зависимости зафиксированы в `pnpm-lock.yaml`.

## Границы MVP

Используйте вымышленные данные для демонстрации на хакатоне. Нет проверки квалификации врача, подтверждения почты, восстановления пароля, клинических шкал, аудита действий и подготовки к работе с реальными медицинскими данными.

Пароли хешируются PBKDF2-SHA256 с индивидуальной солью; в базе сохраняются хеши токенов сессии. Права проверяются на сервере. Сессии используют HttpOnly и SameSite, а на HTTPS — Secure. Для изменений проверяется Origin; предусмотрены ограничения частоты запросов.

Модель может ошибаться. Чат не назначает лечение, не уведомляет врача и не является экстренной помощью. Простые правила перехватывают некоторые сообщения о непосредственной опасности и лекарствах; такие ответы подписаны как служебные сообщения, а не ответы модели. Это не полноценная клиническая оценка риска.
