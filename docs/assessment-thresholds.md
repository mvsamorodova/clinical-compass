# Проверка сигналов по 16 инструментам Clinical Compass v3

Проверено 25.10.2026 по версиям в `lib/assessments.ts`. Это справка для реализации напоминания о плане безопасности и передачи результата врачу. **Высокая выраженность симптомов, суицидальные мысли и текущий суицидальный риск — разные вещи.** Число ниже порога не подтверждает безопасность. В таблице «нет» означает отсутствие подтверждённого общего порога для данной версии/сохраняемых данных, а не отсутствие возможности тяжёлого состояния.

## Сигналы отдельных ответов

Индексы ниже **нулевые**, номера пунктов в названиях — единичные. Все проверки только для существующих, валидных ответов, а не `undefined → 0`.

- `phq9`: `answers[8] > 0` независимо от суммы. Для ответов1–3 на вопрос9 UW/AIMS предусмотрены уточняющие вопросы; решение о срочности принимается специалистом. Это не автоматический вывод о намерении или плане. [Первичный клинический протокол UW/AIMS](https://aims.uw.edu/rmhii/sites/default/files/PHQ-9%20Follow-up%20Questions_Positive%20Question%209_2013.pdf).
- `hdrs17`: `answers[2] > 0` — клинический сигнал содержания пункта3. Значения1/2/3/4 различают обесценивание жизни, желание смерти, высказывания/жесты, попытку. Правило «показать поддержку при любом положительном ответе» — продуктовая мера, не опубликованная отдельная диагностическая отсечка. [КР301_3,Г1](https://cr.minzdrav.gov.ru/preview-cr/301_3).
- `beck_supplied21`: `answers[8] > 0` — прямое признание мыслей в предоставленном тексте. Сумму не вычислять. Правило поддержки основано на содержании ответа, не неизвестном общем ключе.
- `dass42`: `answers[20] > 0` — можно дать мягкое напоминание по тревожащему ответу, но **не маркировать как суицидальный риск**. Разработчик отдельно указывает, что DASS не измеряет суицидальные тенденции. [UNSW,Clinical use](https://dass.psy.unsw.edu.au/over.htm).
- `mfq20_ru`: `answers[10] > 0` относится к мыслям о смерти вообще, а не прямому суицидальному намерению. Допустимо «ответ для обсуждения»; подтверждённой item-level отсечки в адаптации нет. [Шилко и соавт.](https://newpsyresearches.ru/storage/12taLcgLYewyWc3DPAYrWeEKmbO4JhJJStDYm4eN.pdf).
- Для остальных шкал отдельный item-level критерий не подтверждён либо нужные ответы отсутствуют в текущей внешней форме. Не выводить их из общего балла.

## C-SSRS: точные поля текущей формы

`cssrs_lifetime` имеет `recallLabel: "Анамнез за всю жизнь"`, `noTotal:true`. Поля `ideation1`…`ideation5` имеют значения0/1. `ideation3/4/5` доступны при `ideation2===1`; пропуск не является «нет». `most_severe_type` — тип наиболее тяжёлой идеи, не сумма1…5. `frequency`, `duration`, `controllability`, `deterrents`, `reasons` — отдельные характеристики интенсивности.

- `ideation1===1` либо `ideation2===1`: анамнестический положительный ответ для рассмотрения врачом.
- `ideation3===1`, `ideation4===1`, `ideation5===1`: отмечены более конкретные типы идей; сохранять различие содержания и **не объявлять их текущими** только из-за даты заполнения.
- Любое из `actual`, `interrupted`, `aborted`, `preparatory` равное1: сообщённое суицидальное поведение в анамнезе.
- `observed_behavior===1`: поведение в период наблюдения; период хранится свободным текстом `observation_period`, из него нельзя надёжно автоматически получить «за3 месяца».
- `nssi===1`: **отдельное несуицидальное самоповреждение**, не приравнивать к суицидальной попытке.
- `latest_date`, `worst_date`, `first_date` описывают попытки, но не задают давность всех типов идей/подготовительного поведения. Суммы `*_count`, оценки `*_harm`/`*_potential` не подменяют временные окна.

В КР301_3 имеется трактовка тяжести идей≥3 и особенно5/поведения, но её нельзя использовать для вывода о **сегодняшнем** кризисе на основании пожизненной формы. Columbia обозначает наиболее тревожащими идеи4/5 за последний месяц (или после прошлого контакта) и суицидальное поведение за3 месяца (или после прошлого контакта). Текущая форма не собирает эти окна отдельными структурированными полями. Поэтому существующий результат может активировать напоминание/запись для врача с явной пометкой «анамнез», но не автоматическую категорию текущего риска. [Columbia: правила временных окон](https://cssrs.columbia.edu/about-the-project/news-press/announcements/alert-columbia-protocol-tools-appropriate-use-telephone-telemedicine/), [Columbia: scoring guide](https://cssrs.columbia.edu/wp-content/uploads/ScoringandDataAnalysisGuide-for-Clinical-Trials-1.pdf).

## Происхождение проверки КР

Адреса `клиническиерекомендации.рф` в каталоге — зеркало. Числа дополнительно сверены **непосредственно с открытым API официального рубрикатора**, найденным в его публичном frontend: [301_3,официальный текст JSON](https://apicr.minzdrav.gov.ru/api.ashx?op=GetClinrec2&id=301_3), [457_3,официальный текст JSON](https://apicr.minzdrav.gov.ru/api.ashx?op=GetClinrec2&id=457_3). На дату проверки обе записи: `status:0`, `apply_status:"Применяется"`; даты размещения26.08.2024 и19.09.2024. Это подтверждает соответствие проверяемым редакциям2024, а не необходимость самостоятельно менять клиническую схему.

Рекомендация для логики продукта: хранить причину сигнала, версию правила, дату ответа и назначение врача; не заявлять отсутствие риска при отсутствии подсветки. Неподтверждённые пороги оставлять отсутствующими. Кнопка плана доступна независимо от результатов. Все классификации выше предназначены для внимания врача, а не диагноза, назначения лечения или определения необходимости госпитализации.
