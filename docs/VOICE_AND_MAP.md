# Голос, карта и интерфейс — 25 октября 2026

## Голосовые сообщения

Пациент явно скачивает Whisper Tiny (~40 МБ), записывает или выбирает аудио,
прослушивает его и отправляет помощнику. Транскрипция выполняется локально;
в истории показан аудиоплеер. Для ответа помощника отдельно нужна модель Qwen.
Отправка врачу — отдельное действие с именем текущего лечащего врача. Оно не
требует распознавания текста. Пациент может закрыть доступ к записи.

WAV хранится в закрытом R2; API проверяет владельца, явное разрешение и текущую
связь с врачом при каждом чтении. Данные анализа доступны только врачу через
отдельные эндпоинты. Пациентский список не содержит оценок или их метаданных.
После отзыва доступа сохранённый анализ удаляется. Личная переписка остаётся
недоступна врачу.

## GigaAM-Emo

Источник: https://github.com/salute-developers/GigaAM,
commit `7447938d791c4f3e643386ee22c33777004293a5`, официальный checkpoint `emo`.
Лицензия MIT сохранена рядом с весами. Это GigaAM команды GigaChat, а не вызов
чатового API GigaChat.

Веса экспортированы в ONNX и динамически квантованы только для MatMul/Gemm.
Conv оставлен float: полная INT8-конвертация использует ConvInteger, который
не поддерживается выбранным браузерным runtime. Размер 407 859 480 байт;
SHA-256 `8fad2a2c4637799b03bd21c0f3231f66460d688e781d38bcbb14939b40fe42ec`.
33 статических фрагмента загружаются с сайта только по кнопке врача, проверяются по
SHA-256 и кэшируются браузером. Серверные сборки не содержат дубликатов
браузерных workers/WASM. Скрипт воспроизведения: `scripts/export-gigaam-model.py`.

Frontend: mono 16 kHz, FFT 400, hop 160, periodic Hann, reflect padding,
64 HTK mel, power 2, ln с clamp 1e-9…1e9. Фрагменты до 10 секунд;
длительность используется для усреднения четырёх оценок. Они не являются
вероятностью диагноза, истинного настроения или клинического риска и не
влияют на план безопасности. Для работы рекомендуется компьютер: пиковая
память существенно больше размера загрузки.

Проверка на синтетическом русском WAV: совпадение float ONNX с официальным
PyTorch в пределах 2.4e-7; максимальное отклонение INT8 на этом примере 0.0078.
Это проверка экспорта, не клиническая валидация. Полные результаты в
`gigaam-model-validation.json` и `gigaam-official-reference.json`.
Реальный inference в production-браузере, сохранение и повторное чтение
оценок проверены на синтетическом голосе; микрофон пользователя не включался.

## Карта

`locked → available → in_progress → completed`. После первой точки опоры
следующий модуль требует запись в любом дневнике либо метрики за три разных
дня. После базового модуля пациент выбирает тело/мысли; завершение любой
тропы открывает следующий шаг и вторую тропу. Начатые и завершённые модули
сохраняют доступ, в том числе из прежней версии карты.

Проверка доступности выполняется на сервере, закрытые узлы возвращают 409.
Врач видит этапы и выбранную ветку без личных ответов и права редактирования.
Видео поддержки всегда доступно через официальный YouTube iframe; финальный
модуль отдельно посвящён следующему личному шагу.

## Проверки

- TypeScript и production build.
- 61 проверка голосового API: ownership, роли, CSRF, повреждённый/большой WAV,
  идемпотентность, явная передача врачу, отзыв и смена врача, история аудио.
- 56 проверок авторизации и изоляции данных.
- 81 проверка плана безопасности, сигналов и карты; 99 проверок чата/дневника.
- В браузере: сохранение дневника без заметки, фоновая транскрипция и ответ
  помощника, анализ GigaAM у врача, открытие выбранной ветки карты.

Запуск API-тестов — только локально, на вымышленных данных:
`node --experimental-strip-types tests/voice.mjs` (preview на порту 8787).

## Воспроизведение весов и сборка

Большие веса — генерируемые файлы сборки, исключённые из Git.
`node scripts/prepare-gigaam-runtime.mjs --from-onnx /path/emo-matmul-int8.onnx`
проверяет полный SHA-256 официального экспорта и создаёт 33 фрагмента.
Экспорт воспроизводится скриптом `scripts/export-gigaam-model.py` с версиями
Python/torch/ONNX и commit GigaAM, указанными в его заголовке.
При обычном `pnpm build` подготовленные файлы проверяются; в новом checkout
они скачиваются с опубликованного сайта и проверяются по тому же манифесту.
Архив Sites содержит готовые статические веса. Исходный Git-репозиторий —
манифест, лицензию, скрипты воспроизведения и приложение.
